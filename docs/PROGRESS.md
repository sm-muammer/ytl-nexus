## Task log

### Task 3: app shell, route groups, adapters and motion system (done 2026-11-02)

- **Routes:** route groups `(public)`, `(yes)`, `(workspace)` and `control`. A page exists for all 21 Next.js routes in `docs/product.md` (home, `/design`, 19 stubs, plus `/studio` as a fallback where Apache is absent). `/library`, `/yes` and `/control` have their index page only; their child routes arrive with Tasks 7, 15 and 19. `lib/navigation/modules.ts` is the single registry for modules, routes, navigation and footer links; a unit test proves it matches both `docs/product.md` and the files in `app/`.
- **Shell:** skip link in the root layout; `AppShell` supplies header, `main#main-content` (focusable, so the skip link moves focus), footer. Header has global links (from 1280 px), an "All modules" button (a "Menu" button below 768 px) that opens a native `<dialog>` with every module grouped by purpose, and a mode strip showing the Demo or Live badge, the data label and the session. Workspace pages add a module sidebar from 1024 px; `/command/*` has contextual section navigation. The menu is filtered by role (stub session); this is presentation only.
- **Adapters:** `lib/server/adapters` defines the eight adapter interfaces, each with a `live` stub (reports "Not connected") and a `demo` implementation reading `lib/fixtures`. `readMode` accepts only `live` or `demo`; `instrumentation.ts` stops the server at start otherwise. A demo session switcher (exactly four roles, labelled "Demo session", plus a "Visitor view" reset) sets an HttpOnly cookie through a Zod-validated Server Function that does nothing in live mode.
- **Motion:** `MotionConfig reducedMotion="user"` with `LazyMotion`; CSS entrance primitives (fade, rise, stagger); signal-ribbon route transition; React `ViewTransition` page cross-fade; Canvas 2D `AmbientField` with a quality-tier hook (DPR above 2, memory below 4 GB, 60-frame average above 20 ms), pause on hidden tab, static frame under reduced motion. Details in `docs/design/motion.md`.
- **Tests:** 152 unit tests (`npm run check` passes) and 139 end-to-end tests pass against a production build in demo mode: every route renders the shell, axe reports zero serious or critical violations on all 21 routes at 390, 1440 and 3840 px with no horizontal scroll, focus order, mobile menu by keyboard and touch, 44 px targets, footer links, reduced-motion behaviour. The logo test caught a real bug: the footer logo was stretched by a column flex container (fixed with `self-start`).
- **Docs:** new `docs/operations/configuration.md` and `docs/design/motion.md`; updates to `docs/structure.md`, `docs/design-language.md`, `docs/README.md`, `.env.example` and the CI workflow (`NEXUS_MODE=demo`). Spec tasks 3.1 to 3.5 are ticked in `.kiro/specs/ytl-nexus-platform/tasks.md`.
- **Not done on purpose:** the error serializer in spec task 1.3 and the offline-build script in 1.4 (nothing yet returns errors to clients; the adapter network-guard test already runs in `tests/unit/adapters.test.ts`). The Nexus Command particle field, per-module content and `requireRole()` belong to Tasks 8 onward and Task 6. A follow-up review with the skills `design-taste-frontend`, `frontend-design`, `ui-ux-pro-max` and `vercel-react-best-practices` (decision D-020) removed the uppercase eyebrows, card boxes and gradient washes, cut entrance motion to one reveal per page, added menu transitions and pending feedback on the demo switcher, and streamed the service status with Suspense.
